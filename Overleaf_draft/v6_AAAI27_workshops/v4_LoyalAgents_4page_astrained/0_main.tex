\begin{abstract}
We measure the lever a deployer holds over the user of a switchable model: a natural-language contract in the system message that decides how readily the model refuses. We test four preference-trained Llama-3.1-8B models (DPO, PPO, GRPO, and SwiPO, an instruction-conditioned DPO with a mandatory Kullback-Leibler (KL) anchor), each trained with one safety contract and evaluated as trained, with every parent low-rank adapter merged. The pretrained model already follows the contract: with no adapter its strict-minus-permissive refusal gap is 0.299 (95\% interval 0.266 to 0.332). Supervised fine-tuning on one contract removes this lever, and DPO, PPO, and GRPO keep only 0.03. SwiPO as released keeps 0.376 because its chain skips that fine-tuning; retrained on the intended chain it falls to 0.052 (0.020 to 0.082), not separable from DPO (+0.017, $-$0.025 to +0.057). No model's rate of unsafe answers, judged by Llama Guard 3, moves with the contract, and no trained model protects floor requests more than others. Loading only each model's final adapter, as our earlier versions did, inflates every gap to 0.30 to 0.49: an audit of whom a switchable agent serves must load the model that was trained.
\end{abstract}

\section{Introduction}

AI agents increasingly act for people, and inside a language model the question of whom an agent works for has a concrete answer: it works for whoever writes its inputs. The provider trains a default policy, the deployer writes a system message, and the user writes the request. Pooled preference optimization such as DPO \cite{rafailov2023direct} fits that default to the pairwise judgments of all annotators, which, when the annotators' roles are hidden context, ranks answers by a Borda count over them \cite{siththaranjan2024distributional}, a rule nobody chose \cite{conitzer2024social}. Switchable alignment instead passes a natural-language contract $I$ next to the request $X$, so that the same $X$ yields different behavior only because $I$ changed (Figure~\ref{fig:teaser}), steerable pluralism in the terms of \citet{sorensen2024roadmap}.

\input{../common/fig_teaser}


For loyalty the contract has a second reading. $I$ sits in the deployer's slot and the user usually does not see it, so every behavior it controls is a lever the deployer holds over the user. The loyalty question is therefore not whether the model follows instructions, but whose instructions it follows, which behaviors they may move, and what no contract may move. Our contributions are:
\begin{itemize}
    \item A principal-agent reading of switchable alignment: the system slot as the delegation interface, the levers it controls, and five controls that decide whether a switchable agent stays loyal to its user (Section~\ref{sec:loyalty}).
    \item An audit finding for stacked adapters: evaluated without their parents, every model shows a refusal lever of 0.30 to 0.49; as trained, the lever traces to the pretrained model's prompt-following, which fine-tuning on one contract removes and which SwiPO's loss, trained with one contract, does not restore (Section~\ref{sec:results}).
    \item A separation of wording from harm: as trained, no model's rate of unsafe answers moves with the contract, on floor requests or elsewhere, on seen and held-out prompts, even where its refusal wording does (Section~\ref{sec:results}).
\end{itemize}



\section{Whose Contract Does the Agent Follow?}
\label{sec:loyalty}

Four parties stand behind one answer: the provider fixes defaults in training, the deployer writes $I$ into the system message (developer messages in the OpenAI Model Spec \cite{openai2025modelspec}), the user writes $X$, and third parties are affected but write nothing. Conditioning on $I$ moves the choice of behavior out of the annotator pool and into that slot, so whoever chooses $I$ decides what the user receives. Table~\ref{tab:levers} reads each evaluated switch as such a lever; five controls decide whether its holder can turn the agent against the user.
\begin{itemize}
    \item \textbf{Authority.} If a user can write $I$, a permissive contract is a jailbreak; the contract has to arrive through an authenticated, privileged channel held by an accountable principal \cite{wallace2024instruction,south2025authenticated}, a priority current models enforce unreliably \cite{geng2025control,zhang2025iheval}.
    \item \textbf{Disclosure.} The user does not see $I$, so a length cap changes answers without telling them; a contract card, a readable statement of the contract in force, is the switchable form of a disclosure standard.
    \item \textbf{Conflicts of interest.} A deployer can pick the most permissive contract to cut complaints; told to promote sponsors, many models favor the company over the user \cite{wu2026ads}.
    \item \textbf{Limits.} Loyalty to the user is bounded by duties to third parties, as a human fiduciary's is: a floor of behaviors no contract may change, trained with targets that do not depend on $I$, below a switchable layer.
    \item \textbf{Audit.} If the contract in force is logged with every response, a harmful switch can be traced to the principal who set it \cite{chan2024visibility}; varying $I$ with $X$ fixed measures each lever.
\end{itemize}

\section{Conclusion}

As trained, the deployer's contract barely moves a preference-trained model's refusals: the lever is the pretrained model's prompt-following, SFT on one contract removes it, and SwiPO's loss, trained with one contract, does not restore it. No contract moves harmful content. Without their parent adapters the same models show levers of 0.30 to 0.49, so a loyalty audit must load the model as trained, and a loyal agent needs an authenticated, visible contract and a trained floor.
